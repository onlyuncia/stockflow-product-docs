# Кейс-сайт и прототип StockFlow

Готовая статическая версия находится в [`dist/index.html`](dist/index.html). Её можно открыть в браузере двойным щелчком по файлу; установка зависимостей для просмотра не нужна.

Сайт объединяет презентацию кейса, страницы девятнадцати документов, PDF, галерею тринадцати диаграмм и прототип рабочего места менеджера. Документы и PDF формируются из исходников в папке `docs` проекта. Единый кейс доступен на [отдельной странице](dist/documents/case-stockflow.html), PDF - [для скачивания](dist/assets/case-stockflow.pdf).

## Дизайн сайта

Оформление использует [HeroUI styles](https://heroui.com/en/docs/react/getting-started/frameworks#other-frameworks) 3.2.6: классы кнопок, полей, карточек и меток статусов подключены к обычному HTML. Библиотека сохранена локально в `dist/assets/vendor/heroui`, с лицензией и сведениями об источнике. React для просмотра сайта не нужен.

По умолчанию включена тёмная тема. Светлая переключается кнопкой в шапке сайта или рабочего места; выбор сохраняется в браузере и действует на страницах документов и галереи. Палитра использует холодный синий акцент, графитовые поверхности и тонкие границы. На компьютере элементы компактные, на сенсорных экранах области нажатия остаются крупнее. Принципы читаемости, фокуса и доступности из Apple HIG сохранены.

Короткие CSS-анимации сопровождают открытие окон, переход к истории и планам, уведомления и нажатие кнопок. При системной настройке уменьшения движения анимации отключаются.

На широком экране список товаров и решение расположены рядом. На телефоне карточки показывают потребность обеих площадок без горизонтальной прокрутки; выбор товара переводит к его решению. Панель подтверждения и утверждения остаётся доступной при прокрутке решения. В истории видно предложенное и утверждённое количество, а также разницу по каждой площадке.

Схемы открываются в окне с кнопками увеличения, уменьшения, «Вместить» и «100%». Увеличенное изображение можно перемещать мышью, прокруткой или стрелками клавиатуры после фокуса на области просмотра. Клавиши `+` и `−` меняют масштаб, `0` возвращает общий вид. На телефоне доступна прокрутка пальцем.

## Прототип

На синтетических данных доступны просмотр потребности, подтверждение своего остатка, изменение предложенной отгрузки и закупки, утверждение и отказ. История сохраняет исходное предложение и решение отдельно. Утверждённые планы можно скачать в CSV.

Переключатель «Ситуация» показывает отсутствие продаж, отсутствие правила, нулевой спрос и достаточный свой запас. Он создаёт новые демонстрационные рекомендации, сохраняя прежнюю историю. Связи с реальными API и сервером нет. Данные сохраняются только в локальном хранилище браузера; кнопка «Сбросить демо» очищает только данные StockFlow.

## Обновление страниц документов

После изменения документов или диаграмм выполните из папки `prototype` (Node.js 24 или новее и Python 3.12):

```powershell
npm ci
python -m pip install -r requirements.txt
npm run build
```

Сборка создаёт PDF из `docs/case-stockflow.md`, обновляет страницы документов и каталог схем, затем проверяет ссылки, копии исходников и OpenAPI. В PDF добавляются четыре приложения с готовыми PNG из `assets/diagrams`: BPMN AS IS, BPMN TO BE, C4 Containers и ERD «Предложение, решение и планы». Изображения используются без перерисовки и обрезки, с сохранением пропорций; BPMN размещаются на A3 landscape, C4 — на A4, широкая ERD — на A2 landscape для читаемости полей. Изображения доступны в документации и галерее сайта. Шрифты PDF включены в `assets/fonts` вместе с лицензией; внешняя загрузка шрифтов при сборке не нужна. Исходный PDF находится в `output/pdf/case-stockflow.pdf`, публичная копия - в `dist/assets/case-stockflow.pdf`.

Изменения HTML, CSS и поведения прототипа в `dist` применяются напрямую. Генератор не заменяет главную страницу и логику прототипа. Отдельные команды: `npm run build:pdf`, `npm run build:docs`, `npm run check`, `npm test`.

## GitHub Pages

В корне проекта подготовлен `.github/workflows/pages.yml`. После загрузки проекта в репозиторий выберите **Settings → Pages → Source → GitHub Actions**. Workflow публикует именно `prototype/dist`, поэтому по корневому адресу сайта откроется презентация с прототипом.

Workflow запускается при изменении документов, диаграмм, прототипа и README в основной ветке репозитория, а также вручную через **Actions → StockFlow Pages → Run workflow**. Перед публикацией он устанавливает зафиксированные зависимости, выполняет тесты демо, пересобирает PDF и страницы и проверяет ссылки и OpenAPI. Файлы `prototype/dist` нужно включить в репозиторий вместе с исходниками. Локальное наличие workflow не означает, что сайт уже опубликован.

Настройка основана на [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Публикация в рамках этой работы не выполнялась.

## Проверка поведения

```powershell
npm test
```

Проверяются расчёт примера, округление распределения, ограничения количества, отказ, отдельные планы, неизменность истории и повторное утверждение. Эти проверки относятся к прототипу, а не к работающему backend StockFlow.
